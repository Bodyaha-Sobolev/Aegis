# Aegis — язык и IDE как один проект

Один Rust workspace, одно ядро языка. `aegis-studio` использует тот же компилятор,
диагностику и формат защищённых исходников, что и `aegis-cli`.
Основной результат компиляции — самостоятельный Windows x64 EXE.
Обязательной ВМ и браузерной оболочки нет.

Исходники и обновления: [Bodyaha-Sobolev/Aegis](https://github.com/Bodyaha-Sobolev/Aegis).
Скачать IDE и CLI: [ранние сборки Aegis](https://github.com/Bodyaha-Sobolev/Aegis/releases).
Windows CI запускает проверки и собирает IDE/CLI; готовые EXE доступны в
артефакте `aegis-windows-x64` успешной сборки.

## Быстрый старт

Нужны Windows 10/11 x64, Rust 1.96+ и средства сборки MSVC / Windows SDK.
В текущей среде они уже установлены. Python 3.11+ нужен для интеграционных проверок.

```powershell
.\build.cmd                           # release-сборка всего проекта
.\aegis.exe                           # IDE
.\aegis-cli.exe build examples\factorial.ae factorial.exe
.\factorial.exe
.\build.cmd test                      # форматирование, lint, unit и native-тесты
```

Для разработки: `cargo run -p aegis-studio`, `cargo run -p aegis-cli -- --help`.
Зависимости фиксируются в `Cargo.lock`; в `.cargo/config.toml` сборка ограничена
четырьмя параллельными задачами. Первая сборка загружает и компилирует зависимости.

## Что реализовано

Компилятор написан на Rust, самостоятельно формирует x86-64 код и PE32+:

- функции с 0–32 аргументами, вызовы вперёд, рекурсия и `main`;
- 64-битная целочисленная арифметика, `let`, присваивания и блочные области;
- типы `i64`, `u64`, `bool`, аннотации/вывод типов, проверка аргументов и результатов;
- явные преобразования, знаковые/беззнаковые деление, сравнения и печать;
- локальные массивы `[i64; N]` / `[u64; N]` / `[bool; N]`, копирование значений,
  `len`, чтение/запись с проверкой границ (ошибка индекса — exit 72);
- именованные `struct` со скалярными полями, проверяемые инициализаторы,
  доступ к полям, независимые копии и параметры-структуры по значению;
- параметры-массивы по значению, литералы в аргументах, независимые копии в функциях;
- неизменяемые UTF-8 `str`, Unicode escapes, параметры/возврат строк, массивы str,
  `print`/`println`, сравнение по содержимому, длина и проверяемая индексация байтов;
- строковые данные в отдельной read-only, non-executable секции EXE;
- условия, циклы, `break`, `continue`, `return`;
- сравнения, `!`, `&&` и `||` с сокращённым вычислением;
- побитовые `& | ^ ~`, сдвиги `<< >> >>>`, двоичные литералы `0b1010`;
- размер кадра стека по живым переменным, повторное использование слотов блоков;
- `printi`, `printc`, `exit`, UTF-8 комментарии и BOM;
- свёртка полностью константных выражений без изменения порядка побочных эффектов;
- диагностика с исходным диапазоном, строкой и столбцом;
- ограничения размера и глубины, безопасный отказ на ошибочных исходниках;
- деление на ноль завершает программу с кодом 70, переполнение деления — 71.

Studio — нативное графическое приложение на eframe/egui:

- тёмный интерфейс, вкладки, моноширинный редактор и номера строк;
- подсветка на общем лексере, список функций и фоновая диагностика;
- полные сигнатуры функций с типами и одинаковые ошибки типов в CLI и Studio;
- переход к функции/ошибке, поиск и замена, строка/столбец курсора;
- открытие папки с файлами AEGIS, открытие и сохранение UTF-8;
- обновление списка файлов кнопкой Refresh, быстрый поиск по пути через Ctrl+P;
- выбор результата стрелками и Enter, переход к строке и Unicode-столбцу через Ctrl+G;
- защита от потери несохранённых изменений при закрытии вкладки/приложения;
- сборка снимка текущего буфера в фоне, вывод ошибок и параметров сборки;
- запуск отдельного процесса с захватом stdout/stderr, кодом завершения и Stop;
- открытие и сохранение нового защищённого формата с внешним ключом;
- File → Inspect EXE / DLL / SYS: заголовки PE32/PE32+, секции/права доступа,
  обычные импорты по имени/ordinal, фильтр, копирование отчёта, hex/ASCII байтов
  и чтение целых LE/BE; файл не запускается;
- приложение не сохраняет историю документов, ключи, состояние сеанса и подсказки
  моделей на диск. Системные диалоги и ОС могут иметь собственную историю.

Клавиши: Ctrl+N/O/S/W, Ctrl+Shift+S, Ctrl+F, Ctrl+P — файл проекта,
Ctrl+G — строка или `строка:столбец`, F6 — Build, F5 — Build and run.
Именованный исходник собирается в `<полное имя исходника>.exe`; несохранённый
буфер — во временный каталог без записи открытого исходника на диск.

## Защищённые исходники

```powershell
.\aegis-cli.exe keygen D:\keys\project.bin
.\aegis-cli.exe enc program.ae program.aeg -k D:\keys\project.bin -c 0xABC
.\aegis-cli.exe build program.aeg program.exe -k D:\keys\project.bin -c 0xABC
.\aegis-cli.exe dec program.aeg restored.ae -k D:\keys\project.bin -c 0xABC
```

Новый контейнер `AEGIS02`: XChaCha20-Poly1305, случайные соль и nonce при каждом
сохранении, Argon2id и аутентификация заголовка. Используются библиотеки RustCrypto.
Параметры формата фиксированы: Argon2id v19, 19456 КиБ, 2 прохода, 1 линия;
ключ 32 байта, соль 16 байт, nonce 24 байта. Диалект — число 0–4095, его нельзя
рассматривать как самостоятельный стойкий пароль. Ключ-файл — 32–65536 байт;
`keygen` создаёт 32 случайных байта и отказывается перезаписывать существующий файл.

Рабочие ключи хранятся отдельно от проекта. При открытии/сохранении защищённого
файла IDE запрашивает ключ заново и не кэширует путь к нему между операциями.
Сборка защищённого файла обрабатывает исходник в памяти. `dec` намеренно пишет
обычный читаемый файл. Сохранение выполняется через временный файл рядом с целью;
проверяется отказ записи с сохранением старого содержимого.

Исходник открытого редактора и история Undo находятся в памяти. Затирание
управляемых буферов ключей не гарантирует отсутствие всех копий в памяти,
swap, драйверах или дампах. Новый контейнер приложения не прошёл независимый аудит.

## Проверки

```powershell
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace
cargo build --locked -p aegis-cli
py tools\test_native.py
py tools\audit_dependencies.py
```

Native-тесты запускают EXE, полученные новым Rust-компилятором, а не старый
ассемблерный компилятор. Проверяются арифметика, управление, ABI вызовов,
ошибки, защищённая сборка, неверные ключи и сохранность файлов при отказе записи.
Rust-тесты дополнительно проверяют случайные ошибочные входы, ограничения AST,
воспроизводимость кодогенерации, криптоконтейнер, состояние вкладок,
устаревшие результаты анализа и отрисовку egui без графического устройства.

Для проверки настоящего графического окна предусмотрен режим
`aegis-studio.exe --smoke-test <путь screenshot.png>`: он открывает своё окно,
захватывает собственный отрисованный кадр и автоматически завершается.
Он не заменяет полную ручную проверку клавиатуры, IME, диалогов и разных DPI.

Замер компилятора: `cargo run --release -p aegis-lang --example bench`.
Это время полной компиляции примера, не наносекундная задержка формулы.

## Анализ бинарных файлов

В CLI есть `aegis-cli inspect file.exe` (также DLL/SYS). Это ограниченный
read-only PE-парсер на общем ядре: до 64 МиБ, 96 секций, 128 библиотек и
4096 импортируемых символов. Проверяются границы, неоднозначное отображение RVA
и обрывы таблиц. Управляющие байты в именах экранируются. Объявленные NX/ASLR/CFG
флаги не доказывают безопасность программы; подпись не проверяется. Пока нет
экспортов, delay imports, дизассемблера и анализа памяти процесса. Не все
нестандартные/упакованные PE будут приняты строгим парсером.
Формат сверяется со [спецификацией Microsoft PE](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format).

## Что ещё не реализовано

Язык пока небольшой: нет динамических строк, f32/f64, динамических массивов/срезов, вложенных структур, массивов структур, модулей, FFI,
потоков и сетевой стандартной библиотеки. Поэтому на нём сейчас нельзя перенести
Minecraft, готовый backend или большой игровой проект. Нет отладчика, VM,
протектора готовых EXE и совместимости с чужими движками.

В IDE пока нет подключения моделей ИИ, MCP, управления ПК, анализа процессов,
дампов и сетевого трафика. Требования владельца, порядок развития и границы
полномочий записаны в [VISION.md](VISION.md). Язык имеет приоритет над
дальнейшим косметическим расширением IDE.

## Структура и передача работы

```text
Cargo.toml / Cargo.lock      единый workspace и закреплённые зависимости
crates/aegis-lang/           frontend, backend, диагностика, контейнер, запись файлов
crates/aegis-studio/         редактор, вкладки, фоновые задачи, запуск программ
crates/aegis-cli/            консольный доступ к общему ядру
examples/                   исходники AEGIS
tools/test_native.py        интеграционные проверки Rust-компилятора
tools/audit_dependencies.py проверка закреплённых Windows-зависимостей по OSV
legacy/asm/                 сохранённый ассемблерный прототип
HANDOFF.md                  сведения для следующего разработчика/ИИ
```

Старый `AEG0` не поддерживается новым контейнером. Для миграции сначала
декодировать старый файл через `legacy/asm/aegisc.exe`, затем сохранить его
в `AEGIS02`. Не удалять старые ключи до успешной проверки миграции.
Сборка прототипа: `tools\build-legacy.cmd`; его проверки — `py tools\test_legacy.py`.
Для архивного прототипа нужен локальный FASM в `tools\fasm.exe`;
сторонний EXE в репозиторий не включён. Основная Rust-сборка от FASM не зависит.


Повторяющиеся значения массива можно задать кратко: `let buffer = [0; 256];`.
Инициализатор вычисляется один раз; доступны также bool, u64 и неизменяемые str.
Правила типов, копирования и размеров описаны в [LANGUAGE.md](LANGUAGE.md).
