# AEGIS 0.2: текущая Rust-реализация языка

Это описание работающего подмножества, которое будет расширяться.

## Программа

```text
fn add(a, b) {
    return a + b;
}

fn main() {
    let answer = add(20, 22);
    printi(answer);
    return 0;
}
```

Обязательна ровно одна функция `main` без параметров. Порядок функций не важен.
У каждой функции не более 32 параметров. Параметры могут иметь типы `i64`,
`u64`, `bool`, `str`, фиксированные массивы этих типов и именованные структуры.
Результатом может быть также массив или структура — по значению. Для составного
результата обязателен явный return на каждом пути; анализ консервативный и не
доказывает возврат из циклов или по константному условию без else.
Без аннотации параметр или результат имеет тип `i64`.
`main` возвращает `i64`. Падение через конец скалярной функции возвращает 0, false или пустую str.
Имена состоят из ASCII-букв, цифр и `_`, начинаются с буквы или `_`,
регистр учитывается. Unicode разрешён в комментариях и строках.

## Модули и имена

```text
mod world {
    struct Point { x: i64, y: i64 }
    fn initial() -> Point { return Point { x: 1, y: 2 }; }
    mod math {
        fn score(point: Point) -> i64 { return point.x + point.y; }
    }
}
fn main() {
    let point = world::initial();
    printi(world::math::score(point));
}
```

`mod name { ... }` объявляет пространство имён внутри текущего исходника.
Модуль может содержать функции, структуры и другие модули. Порядок объявлений
не важен. Короткое имя типа или вызываемой функции ищется сначала в текущем
модуле, затем в родительских до корня. Так же разрешается относительный путь
`math::score`; начальное `::` принудительно задаёт корневой путь.

Функции и структуры в разных модулях могут иметь одинаковые короткие имена.
Полное имя структуры определяет её номинальный тип: `a::Point` и `b::Point`
несовместимы, даже при одинаковых полях. Сигнатуры и список функций IDE показывают
полные имена. Локальные переменные, параметры и поля остаются обычными именами
без `::`. Функция `main` должна находиться именно в корне; `game::main` может
быть обычной функцией и не заменяет точку входа.

Объявление модуля нельзя повторить или открыть заново. До 128 модулей,
вложенность до 16, путь до 17 компонентов (16 модулей и имя элемента). Лимиты
128 структур и 256 функций общие для всего исходника. `mod` — зарезервированное
слово. Все элементы пока доступны через путь: приватность и
пакеты ещё не реализованы. Файловые модули загружаются через API проекта,
описанный ниже; обычный compile(source) остаётся API без файлового доступа. Модуль не является границей
изоляции или разрешений. Результат по-прежнему один нативный EXE.

### Импорты и короткие имена

```text
mod model { struct Point { x:i64 } fn make()->Point { return Point { x:42 }; } }
use model::Point as P;
use model::make;
use model as m;
fn main() { let p:P=make(); let q=m::Point { x:p.x }; printi(q.x); }
```

`use path;` привязывает последний компонент пути, `use path as name;` задаёт
другое имя. Импортировать можно функцию, структуру или целый модуль; псевдоним
модуля допустим в начале пути к его элементу. Импорты объявляются только на
уровне программы/модуля, требуют `;` и действуют во всём модуле и его потомках,
независимо от порядка файлов и объявлений. Ближайший импорт перекрывает внешний;
если он обозначает структуру, вызов этого имени не переключится на одноимённую
внешнюю функцию. Начальное `::` обращается напрямую к исходному пути от корня,
минуя короткие имена. Локальные переменные и поля не импортируются.

Цель импорта ищется среди настоящих объявлений сначала в текущем модуле,
затем в родительских и корне; `use ::model::Point as P;` фиксирует корень.
Цель не может ссылаться через другой импорт: цепочки, циклы, re-export,
wildcard и групповые импорты пока не поддерживаются. Ошибочен даже неиспользуемый
импорт отсутствующего элемента. Имя не может повторять импорт, функцию,
структуру или модуль в той же области. До 256 импортов на всю программу.
`use` и `as` — зарезервированные слова.

Импорт не создаёт новый тип и не делает копию функции: ABI, номинальная
идентичность структуры, полные имена в сигнатурах IDE остаются прежними.
Это работает и для inline-модулей, и для файлового project API; диагностика
ошибочного импорта указывает на исходное объявление в нужном файле.

### Файловые модули и API проекта

В `main.ae` можно написать `mod world;`. CLI `build`/`check` и IDE загружают
`world.ae` рядом с входным файлом. Внутри world декларация `mod math;` загружает
`world/math.ae`. То же правило действует для внешнего модуля внутри inline-модуля:
путь определяется полным пространством имён от каталога входного файла.
Внешний файл содержит элементы своего модуля без дополнительного `mod world {}`.
Пример из нескольких файлов: `examples/project/main.ae`.

Общий Rust API `aegis_lang::project::compile(entry, source, overlays)` принимает
путь входа, его текст в памяти и необязательные именованные снимки зависимостей.
Отсутствующий вход/модуль допустим, если его текст передан в памяти и родительский
каталог существует. Сам API не пишет исходники. `Build.sources` перечисляет
загруженные пути, а `FunctionInfo.path`/`Diagnostic.path` вместе со span относятся
к оригинальному файлу. Строки и Unicode-столбцы ошибок также оригинальные.
Обычные compile/analyze работают только с переданным текстом и не читают модули.

До 64 файлов с входом, до 1 МиБ оригинальных текстов и развёрнутого исходника,
до 65536 токенов проекта; прежние лимиты модулей/типов/кода сохраняются.
Повторная загрузка одного физического пути и циклы запрещены. Загрузчик принимает
только имена модулей языка, строит пути сам и проверяет канонический путь: выход
через символические ссылки/junction за реальный каталог входа отклоняется.
Это проверка загрузчика, не OS-песочница и не гарантия против одновременной
враждебной подмены файловой системы. Файл считывается один раз в снимок; несколько
чтений не являются транзакцией файловой системы. Фоновый watcher ещё отсутствует.

Модули на диске должны быть UTF-8 `.ae` (BOM допустим). Вход CLI может быть
защищённым `.aeg`, но загрузчик не запрашивает ключи для зависимостей. IDE может
использовать уже разблокированный текст открытого буфера. Нельзя направлять
выход сборки на вход или загруженный модуль: CLI отклоняет такое совпадение.

В IDE `main.ae` автоматически выбирается входом проекта при открытии, а File →
Use active file as project entry задаёт другой вход. F5/F6 используют этот вход,
даже при редактировании зависимого файла в его каталоге. Clear project entry
возвращает сборку активного файла. Все открытые именованные буферы под корнем
передаются снимками: сохранять их для сборки не требуется. Бюджет снимков IDE —
до 64 открытых файлов и 4 МиБ; реальный загружаемый проект всё ещё ограничен 1 МиБ.
Защищённый вход должен оставаться открытым/разблокированным. Refresh повторяет
анализ после внешних изменений. Символы и ошибки открывают нужный файл и не
перезаписывают уже открытый несохранённый текст.

## Типы и преобразования

```text
fn enabled(flags: u64, mask: u64) -> bool {
    return (flags & mask) != 0;
}
fn main() -> i64 {
    let flags: u64 = 0b1010;
    let ready = enabled(flags, 2); // bool выводится из результата функции
    printi(ready);
    return i64(ready);
}
```

`i64` — знаковое 64-битное целое, `u64` — беззнаковое. `bool` имеет только
значения `true` и `false`. `str` — неизменяемая UTF-8 строка.
Скалярный локальный слот занимает 8 байт, массив — по слоту на элемент,
структура — сумму слотов всех полей (включая вложенные).
Тип `let` выводится из инициализатора или указывается после `:`. Присваивание,
аргументы и `return` должны совпадать по типу. Неявных преобразований именованных
значений нет; арифметика и побитовые операции над bool запрещены.

Целый литерал получает `i64` по умолчанию или целый тип из аннотации, аргумента,
результата либо другого операнда. Все 64 бита литерала сохраняются: например,
`let x: i64 = 0xFFFFFFFFFFFFFFFF` хранит -1. Переполнение литерала за 64 бита
отвергается. Само представление не доказывает, что десятичное значение помещается
в положительную часть i64; проверяемые числовые преобразования пока не добавлены.

Явные преобразования записываются как `i64(value)`, `u64(value)`, `bool(value)`.
Между целыми сохраняются биты; bool преобразуется в 0/1, целое в bool — по
проверке на ненулевое значение. Преобразование вычисляет операнд с его собственным
типом и затем переводит результат: `u64(-1 / 2)` равно 0,
а `u64(-1) / 2` равно 9223372036854775807.

Сравнения и логические операции возвращают bool. Поэтому прежнее
`fn less(a,b) { return a < b; }` теперь требует `-> bool` либо `i64(a < b)`.
Ошибки типов проверяются также в недостижимых ветках и за сокращённым `&&`/`||`.

## Выражения

Литералы: `42`, `0x2A`, `0X2a`, `0b101010`, `0B101010`. Хранятся 64 бита; отрицательное число задаётся
унарным минусом. Литерал шире 64 бит отвергается.
Арифметические операции работают с младшими 64 битами, переполнение не проверяется.
Деление, остаток и сравнения определяются типом операндов: для i64 они знаковые,
для u64 — беззнаковые. Знаковое частное округляется к нулю.
Деление на ноль завершает процесс с кодом 70, переполнение знакового деления — 71.

Приоритет от высокого к низкому: скобки/вызовы; унарные `+ - ! ~`;
`* / %`; `+ -`; `<< >> >>>`; все сравнения; `&`; `^`; `|`; `&&`; `||`.
`&`, `|`, `^`, `~` работают над 64 битами; оба операнда бинарной операции
вычисляются слева направо без сокращения. `<<` сдвигает влево, `>>` вправо
с сохранением знака для i64 и с заполнением нулями для u64;
`>>>` всегда сдвигает вправо с заполнением нулями. Число позиций — младшие
6 бит правого операнда: сдвиг на 64 равен сдвигу на 0, на -1 — на 63.
Это правило одинаково для констант и значений времени выполнения.
Для проверки маски используйте `(flags & mask) == value`: сравнения имеют
более высокий приоритет, чем побитовые операции.
Бинарные операции одного приоритета выполняются слева направо.
Сравнения и `!` возвращают bool. Ноль в условии означает false,
любое другое значение — true. `&&` и `||` вычисляют правую часть только при
необходимости и возвращают bool. Числовые условия сохраняются для совместимости.
Полностью константные чистые выражения
сворачиваются при компиляции; поведение арифметики от этого не меняется.

Аргументы вызова вычисляются слева направо. Поддерживаются вложенные вызовы
и рекурсия. Несовпадение числа параметров обнаруживается при сборке.

## Строки

```text
fn message() -> str { return "Привет, \u{1F642}"; }
fn main() {
    let text: str = message();
    println(text);
    printi(len("Привет")); // 12 байт, не 6 символов
    printi("Aegis"[0]);    // 65, байт с индексом 0
    printi(text == message());
}
```

Литералы заключаются в двойные кавычки. Поддерживаются `\n`, `\r`, `\t`,
`\0`, `\\`, `\"`, `\u{HEX}` (1–6 hex-цифр корректного Unicode scalar).
Суррогаты, значения выше U+10FFFF, неизвестные escape-последовательности и
неэкранированные управляющие символы/переносы строки отвергаются. UTF-8
валидируется при сборке. Встроенный NUL разрешён и учитывается в длине.

`print(str)` выводит UTF-8 байты без дополнительного символа; `println(str)`
дописывает LF. Функции могут принимать и возвращать str. Копирование переменной
копирует неизменяемое значение без копирования байтов. Переприсвоить переменную
другой строкой можно, изменить отдельный байт строки — нельзя.

`len(str)` возвращает i64: число UTF-8 байтов. `text[index]` возвращает u64:
байт 0–255. Индекс i64/u64 проверяется до чтения; вне диапазона — exit 72.
Сначала вычисляется строка, затем индекс. Индексация не декодирует Unicode
символы, а len не считает grapheme clusters. `==` / `!=` сравнивают длину и байты,
без Unicode-нормализации. Арифметика, упорядочивание, числовые преобразования и
использование строки как bool-условия запрещены.

Пока str может происходить только из литерала, параметра, переменной, элемента
массива или результата функции с таким значением. Все байты живут в read-only
секции EXE до завершения процесса, поэтому возврат не ссылается на завершённый
стек функции. Это внутреннее представление не доступно как числовой указатель.
Литералы хранятся открытым текстом в EXE; секция не является шифрованием.
Динамическая конкатенация, форматирование, срезы, загрузка строк из I/O и
управление heap-памятью ещё не реализованы.

## Массивы

```text
let values: [i64; 3] = [10, 20, 30];
let copy = values;
copy[0] = 99;
values = [values[2], values[0], values[1]];
printi(len(values)); // 3
printi(copy[0]);     // 99
```

Локальные массивы имеют фиксированный размер от 1 до 256 элементов одного
типа: скалярного (`i64`, `u64`, `bool`, `str`), структуры или другого массива.
Тип указывается как `[u64; 4]`, `[Actor; 8]`, `[[i64; 4]; 3]` либо выводится из
литерала. Все элементы обязательны; допускается завершающая запятая. Пустые
массивы не поддерживаются. Полная раскладка каждого составного типа ограничена
256 слотами по 8 байт; размер массива структур зависит от размера структуры.
Общая глубина вложенности массивов и структур — не более 32.

Массив — владеющее значение: `let copy = values` и `copy = values` копируют
элементы. Изменение копии не меняет оригинал. При присваивании литерала все
элементы правой части вычисляются слева направо до первой записи в целевой
массив, поэтому перестановка `values = [values[1], values[0], values[2]]`
сохраняет старые значения. Размер и тип элементов должны совпадать.

`array[index]` читает элемент, `array[index] = value` изменяет его. Индекс —
i64 или u64; каждый доступ проверяет `0 <= index < len(array)` до обращения
к памяти. Отрицательный или слишком большой индекс завершает процесс кодом 72.
В присваивании сначала вычисляется и проверяется индекс, затем правая часть.
`len(array)` возвращает i64 — число элементов текущего измерения, а не число
скалярных слотов. Содержимое массива не читается, но выражение пути вычисляется:
`len(matrix[index()])` вызывает index и проверяет границы внешнего массива.

Индексирование и len требуют путь от именованной локальной переменной/параметра:
поддерживаются `actors[i].position.x`, `matrix[row][col]`, `len(world.actors)`.
Временный литерал напрямую индексировать пока нельзя. Массивы передаются в функции по значению:

```text
fn first(values: [i64; 3]) -> i64 {
    values[0] = values[0] + 1;
    return values[0];
}
fn main() {
    let source = [10, 20, 30];
    printi(first(source));       // 11
    printi(source[0]);           // 10, оригинал не изменён
    printi(first([1, 2, 3]));   // 2
}
```

Каждый аргумент вычисляется и сохраняется слева направо. Параметр получает
собственную копию; передача одного массива в два параметра создаёт две
независимые копии. Тип и размер проверяются при сборке. Литералы разрешены
также в аргументах массива. Компилятор пока выполняет копирование явно,
без устранения лишних копий и без неявного заимствования.

Массивы не преобразуются в числа, bool или неограниченные указатели и не могут
использоваться как условие. Срезы,
динамические размеры и модель заимствований ещё не реализованы. Элемент
занимает свою полную рекурсивную раскладку; суммарно именованные живые массивы, скаляры и
параметры функции должны помещаться в 256 слотов. Снимки аргументов и вычислений
хранятся дополнительно на стеке. Память завершённых блоков переиспользуется,
но гарантированного стирания содержимого стека нет.

### Повторяющийся инициализатор массива

```text
let scratch = [0; 256];
let masks: [u64; 4] = [0xffffffffffffffff; 4];
let labels = ["ready"; 3];
```

`[expression; N]` создаёт массив из N копий значения, включая структуру или
вложенный массив. Размер N — целочисленный литерал от 1 до 256; выражения размера
и нулевые массивы пока не поддерживаются. Полная раскладка должна поместиться
в 256 слотов. Выражение-инициализатор
вычисляется ровно один раз, в том числе при вызове функции, а затем копируется.
Тип элемента определяется аннотацией или типом выражения. Литерал работает в
объявлении, присваивании всего массива и аргументе функции. При `a = [a[0]; N]`
значение читается до изменения элементов a. Для str копируется дескриптор
неизменяемой строки. Все прежние проверки индексов и лимит 256 живых слотов
сохраняются; это не динамический массив и не выделение памяти в куче.

## Именованные структуры

```text
struct Entity {
    name: str,
    x: i64,
    flags: u64,
    active: bool,
}
fn score(entity: Entity) -> i64 {
    entity.x = entity.x + 1;
    return entity.x;
}
fn main() {
    let player = Entity { x: 10, name: "player", active: true, flags: 3 };
    let copy: Entity = player;
    copy.x = 20;
    printi(score(copy)); // 21; copy.x остаётся 20
    println(player.name);
}
```

Структура объявляется на верхнем уровне; её можно использовать раньше объявления.
До 128 структур, от 1 до 256 уникальных полей. Поле может иметь тип
`i64`, `u64`, `bool`, `str`, любого поддерживаемого фиксированного массива или
другой структуры.
Циклы типов запрещены даже для неиспользуемых определений. Глубина вложенности
не более 32 составных уровней (структуры и массивы вместе), суммарная раскладка каждой — не более 256 слотов. Типы номинальные: структуры с разными именами не
совместимы, даже если наборы полей одинаковы. Все поля инициализируются явно
ровно один раз; неизвестные/пропущенные поля и ошибки типов отклоняются.
Порядок полей в инициализаторе произвольный. Выражения вычисляются слева направо
в порядке написания, перед записью полей назначения.

`value.field` читает или меняет поле именованной локальной структуры/параметра;
поддерживаются цепочки `entity.position.x`, индексация `entity.history[i]` и
`len(entity.history)`. Вложенное поле можно скопировать в переменную, передать
в функцию или присвоить целиком. Присваивание с перекрытием использует полный
снимок правой части до изменения назначения.
Объявление, присваивание целой структуры и аргумент функции копируют значение;
изменение копии не меняет оригинал. Каждый вызов получает собственные слоты.
Строковые поля разделяют только неизменяемые строковые данные. Отдельный байт
строкового поля менять нельзя. Неявного преобразования структуры в число,
указатель, условие или массив нет; сравнение структур пока отсутствует.

Локальное размещение: скаляр занимает 8 байт, массив и вложенная структура
размещаются последовательно внутри родителя в порядке объявления. Общий
лимит живых слотов функции (включая параметры, массивы и скаляры) — 256.
Снимки выражений/аргументов временно занимают дополнительный стек. Внутренний ABI
копирования не является C-совместимой раскладкой. Пока отсутствуют
методы, доступ
к полю временного объекта, `sizeof` и указатели на поля. Гарантированного
стирания освобождённых слотов нет.

Пример составного значения:

```text
struct Position { x: i64, y: i64 }
struct Actor { position: Position, samples: [i64; 4] }
fn main() {
    let actor = Actor { samples: [0; 4], position: Position { x: 3, y: 4 } };
    actor.position.x = 5;
    actor.samples = [actor.position.x; 4];
    let position = actor.position; // независимая копия
    printi(actor.samples[3]);
}
```

Массивы структур и матрицы:

```text
struct Point { x: i64, y: i64 }
fn main() {
    let points = [Point { x: 1, y: 2 }; 4];
    points[2].x = 10;
    let matrix = [[0; 3]; 2];
    matrix[1][2] = points[2].x;
    let row = matrix[1]; // независимая копия
    printi(len(matrix));    // 2
    printi(len(matrix[0])); // 3
}
```

## Возврат составных значений

```text
struct Point { x: i64, y: i64 }
fn move(point: Point, dx: i64) -> Point {
    point.x = point.x + dx;
    return point;
}
fn make() -> [Point; 2] {
    return [Point { x: 1, y: 2 }; 2];
}
fn main() {
    let points = make();
    points[0] = move(points[0], 3);
    printi(points[0].x);
}
```

Возвращаемое значение копируется в буфер вызывающей функции до завершения
вызванной. Оно не ссылается на локальные переменные завершённого вызова.
Поддерживаются рекурсия, вложенные вызовы, литералы, локальные значения и
составные пути в return; тип и форма результата должны совпадать с сигнатурой.
Возвращённое значение можно сохранить, присвоить составному месту, передать
как аргумент или использовать в инициализаторе. При игнорировании результата
временный буфер освобождается. Прямой доступ к полю/индексу временного результата
пока требует сначала сохранить результат в переменную.

Внутренний ABI передаёт закрытый адрес буфера результата через R10, отдельно
от 0–32 исходных аргументов. Вызванная функция сохраняет его в дополнительном
служебном слоте. Это не указатель языка и не обещание совместимости с C ABI.
Служебный слот и временные буферы не входят в лимит 256 именованных слотов;
общая глубина рекурсии всё ещё ограничена стеком процесса.

## Переменные и управление

```text
let i = 0;
while (i < 10) {
    if (i % 2 == 0) {
        printi(i);
    } else {
        printc(46);
    }
    i = i + 1;
}
```

`let` требует инициализатор; переменная доступна после объявления до конца блока.
Использование до объявления и повтор имени среди активных переменных запрещены.
Затенение активной переменной пока не поддерживается. Переменные из завершённых
блоков недоступны. `return expression` выходит из функции.
`break` завершает ближайший цикл, `continue` переходит к его следующей проверке
условия. За пределами цикла обе инструкции отвергаются при сборке.
Точки с запятой после простых инструкций необязательны.

`printi(expression)`, `printc(expression)`, `exit(expression)`, `print(str)`,
`println(str)` — встроенные
инструкции, а не значения выражений. `printi` печатает число согласно типу
(для bool — 0/1) и LF;
`printc` выводит младший байт; `exit` завершает процесс с младшими 32 битами кода.
Возвращаемое значение `main` также становится кодом завершения процесса.

Пока нет динамических строк/массивов, типов иной ширины, вещественных чисел, указателей, произвольного доступа к памяти, внешних вызовов,
пакетов, приватности модулей и FFI. Добавление этих возможностей — следующий
этап развития языка; ориентир остаётся на нативный низкоуровневый доступ.

## Ограничения прототипа

- Исходный текст — до 1 МиБ; до 65536 токенов плюс конец файла.
- До 256 функций, 256 одновременно живых локальных слотов на функцию (включая параметры); число вызовов ограничивается
  размером машинного кода и исходника.
- До 64 КиБ машинного кода вместе с небольшими служебными процедурами.
- Глубина разбора и дерева выражения ограничена счётчиком 96; вложенные выражения используют
  несколько уровней счётчика на одну пару скобок.
- До 2 МиБ данных строк вместе с длинами и выравниванием.
- Результат — Windows x64 PE32+ с .text, .idata и read-only .rdata.
  Размер EXE — 68096 байт плюс данные, округлённые до 512 байт;
  минимальный EXE теперь 68608 байт (всегда есть дескриптор пустой строки).
- Файловые пути обрабатываются Rust/std и библиотекой атомарной записи;
  длинные пути зависят также от конфигурации Windows.
- В EXE пока нет отладочных символов и таблиц unwind. Кроме свёртки констант
  оптимизирующие проходы пока отсутствуют.

Размер кадра стека определяется максимальным числом живых локальных переменных
и округляется до 16 байт. Завершённые блоки освобождают слоты для следующих
блоков. Первые четыре аргумента передаются в регистрах, остальные — через стек
по Windows x64 ABI для скалярных значений. Для массивов используется внутренний
ABI Aegis (также для структур): адрес снимка у вызывающего кода, который функция копирует в собственные
слоты после сохранения всех входных регистров. Этот ABI не является обещанием
совместимости массивов или структур с C/FFI. Глубина рекурсии всё ещё ограничена стеком процесса;
автоматического увеличения и собственного обработчика переполнения стека нет.

Компилятор прекращает сборку с диагностикой при превышении своих лимитов.
Синтаксические и семантические ошибки выводятся как `ERROR строка:столбец: причина`.
Столбец считается по Unicode-символам. Диагностика CLI идёт в stderr.
Успешный CLI возвращает 0, ошибка — 2.

### Релокации и ASLR в нативном EXE

Генератор создаёт PE32+ с NX, DynamicBase, HighEntropyVA и LARGE_ADDRESS_AWARE.
Предпочтительная база — 0x140000000. .text исполняема и доступна для чтения,
.idata доступна для чтения/записи без исполнения, .rdata — только для чтения,
.reloc — только для чтения, без исполнения и с флагом discardable.

Все ссылки на код/строки/импорты сейчас относительны RIP или представлены RVA.
Абсолютных адресов образа нет, поэтому .reloc содержит блок на 12 байт с
ABSOLUTE padding entries, не меняющий данные. Директория позволяет загрузчику
перемещать образ, в том числе при обязательном ASLR с требованием релокаций.
Если backend добавит абсолютные адреса, он обязан формировать реальные fixup
entries; существующий пустой блок не сможет исправить такие ссылки.

Формат соответствует [Microsoft PE](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format).
В native-тестах процесс создаётся с локальной политикой обязательного ASLR через
[UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute).
Из документированного CREATE_PROCESS_DEBUG_EVENT берётся фактическая база;
проверяются перенос выше 4 ГиБ и ожидаемое завершение. Тест не читает/не меняет
память процессов и не меняет настройки Windows. Флаги заголовка сами по себе не
доказывают безопасность приложения. CFG, unwind/debug-таблиц пока нет;
ASLR не является протектором или гарантией от реверс-инжиниринга.

### Экспорты PE в инструментах CLI/IDE

Общее ядро pe::inspect разбирает export directory PE32 и PE32+ без загрузки файла.
Image.export_library — необязательное имя DLL, Image.exports — непустые слоты
export address table с ordinal, всеми именами, RVA, необязательной строкой
forwarder и file_offset при однозначном отображении в файл. Нулевой слот EAT
пропускается; отсутствие имени не удаляет ordinal-only export. Индекс из name
ordinal table — unbiased индекс EAT, к нему прибавляется OrdinalBase.

Forwarder определяется попаданием RVA в диапазон export data directory, его
строка должна завершаться NUL внутри этого диапазона и raw region. Таблицы
адресов, имён и ordinal могут размещаться отдельно от directory. Строка forwarder
показана как данные: импорт из другого модуля не разрешается и DLL не загружается.
Для обычного target без однозначных raw bytes file_offset отсутствует; такой
RVA остаётся виден, поскольку экспорт может обозначать BSS, данные или absolute,
а не только исполняемую функцию. Это не проверка совместимости ABI и не FFI.

Лимиты: 65536 адресных слотов, 65536 имён, 512 исходных байт на имя/forwarder,
общий бюджет имён import+export 1 МиБ. Непечатаемые байты экранируются. Проверяются
переполнение ordinal и границы таблиц; ссылка имени на пропущенный/вне-диапазонный
слот отвергается. Forwarder выводится один раз на ordinal, затем его имена —
отдельно, чтобы длинный target с множеством алиасов не раздувал отчёт.

CLI inspect включает раздел Exports. IDE показывает виртуализированную вкладку
Exports, фильтр по имени/DLL/ordinal/RVA/forwarder и переход File к байтам того же
снимка. Имена обрезаются по ширине строки, полный текст доступен при наведении.
Фильтр кэшируется до изменения запроса. Для визуальной проверки вкладки доступен
`aegis.exe --smoke-inspect screenshot.png fixture.dll exports`.

### Линейное дизассемблирование x86/x64

Модуль disasm — собственный адаптер над временно vendored iced-x86 1.21.0,
features std/decoder/intel; кодирование/assembler выключены. Реализация декодера
не объявляется собственной. Версия и архив SHA256 закреплены в third_party,
исходные .rs не менялись. Изменён только manifest для двух compatibility lints.
Собственные crate сохраняют forbid(unsafe_code); это не запрет unsafe внутри
сторонней библиотеки и не доказательство её полной безопасности.

API decode(bytes,bits,address,limit) принимает 32/64 bit, до 65536 байт,
1..4096 инструкций, возвращает Row с VA, offset, bytes, Intel text, invalid
и direct branch target. Проверяются продвижение декодера и переполнение адреса.
Page для PE использует уникальный raw range и совпадающий по размеру снимок,
вычисляет VA=ImageBase+RVA, next_rva и file offset. Machine должен быть x86/x64.
Метаданные Image и bytes должны относиться к одному снимку, как в CLI/IDE;
проверка размера сама по себе не проверяет тождество произвольных буферов.

CLI: disasm PE [RVA] [count], по умолчанию entry/128 инструкций. RVA decimal
или 0x hex, неправильный RVA/count/architecture — диагностический exit 2.
Неполные/неверные инструкции показаны с [invalid], не выдаются за достоверный код.
IDE кеширует страницу по запросу, 128 инструкций, bounded history до 128 RVA,
Go/Entry/Back/Next, Follow для прямых ветвей с raw mapping, переход к байтам
того же снимка. В Exports кнопка Disasm не предлагается для forwarder/BSS.
Smoke: --smoke-inspect PNG PE disasm. Данные не загружаются и не исполняются.
Нет анализа CFG/типов, восстановления функций, декомпиляции и live-debugger.
